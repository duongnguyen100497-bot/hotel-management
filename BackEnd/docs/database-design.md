# PostgreSQL database design

## Data conventions

- All primary keys are `uuid` with `gen_random_uuid()`. Human-readable booking/invoice/reference codes are generated separately and unique; UUIDs are API identifiers. This avoids exposing sequence volume and supports imports; `bigint` remains a reasonable alternative only if operations require sequential paper IDs.
- All mutable tables: `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`, `version integer not null default 1`; writes use optimistic version where concurrent edits can overwrite data. Financial/history tables are append-only and omit mutable fields as appropriate.
- `timestamptz` is stored/displayed in UTC; property timezone is an IANA string. Stay arrival/departure uses `date`, never timestamp.
- Money is `numeric(14,2)` in VND-compatible amounts. A currency code is stored on financial snapshots; if hotel is VND-only at launch, still seed `VND`.
- Use check constraints for bounded state values rather than PostgreSQL enum types: statuses will evolve and migrations should remain simple. Use normalized tables for amenities/categories/lines; `jsonb` only for sparse metadata/policy snapshot/event payloads, never core relationships.
- Soft archive (`archived_at`) is used for operational reference data. Do not soft-delete audit/financial/security records. Personal data deletion/anonymization is controlled retention work, not normal CRUD.

## Foreign-key deletion rules

Use `RESTRICT` for business/financial/security references. `CASCADE` only for purely dependent, nonhistorical mappings (`role_permissions`, `room_type_amenities`, `room_type_media`) after owner lifecycle checks. `SET NULL` is acceptable for optional historical actor/media/assigned-user references if a user/media retention process removes it; ordinary user deletion is not allowed. No cascade may erase invoices, payments, stays, reservation history, or audit records.

## Concurrency and indexing

Use transaction isolation `READ COMMITTED` plus the reservation exclusion constraint; retry serialization/deadlock/constraint-conflict cases as clear 409 API errors. Apply optimistic `version` to staff edits to room/property/profile records (`If-Match` or version field). GIST needs `btree_gist` extension. Query pagination uses keyset cursor and indexes beginning with selected stable sort/filter columns. Full text/search requirements are modest; use `citext`, normalized fields and trigram indexes only if query plans demonstrate need.
